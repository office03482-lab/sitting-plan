# LOGIN & LOGOUT MINIMAL FIX PLAN

## Login Fixes

### Fix 1: Clear Stale Active Session Key at signIn Start
- **File**: `AuthProvider.tsx:914-917`
- **Logic**: `localStorage.removeItem(ACTIVE_SESSION_STORAGE_KEY)` at the top of `signIn()`
- **Effect**: Prevents stale `X-Active-Session` header from causing 401 on first business requests
- **Risk**: None — key is regenerated by `ensurePortalSessionRegistered` if needed
- **Evidence**: Proven root cause of 401 race in `FIRST_LOGIN_DATA_REQUEST_EVIDENCE.md`

### Fix 2: Parallelize Profile + Memberships Queries
- **File**: `AuthProvider.tsx:276-308`
- **Logic**: `Promise.all([profileQuery, membershipsQuery])` in `buildAppUserFromSession()`
- **Effect**: Reduces login critical path by ~50-200ms (the slower of the two queries instead of their sum)
- **Risk**: None — both queries use the same `userId` and have no data dependency
- **Evidence**: Both queries depend only on `userId` from the session, confirmed in `LOGIN_BOOTSTRAP_WATERFALL.md`

### Fix 3 (Not Implemented — Not Needed):
- Profile+memberships is the only parallelization opportunity. Permissions depends on memberships result.
- Registration is already fire-and-forget. No change needed.

## Logout Fix

### Fix 3: Reorder signOut — Local State First, Remote Best-Effort
- **File**: `AuthProvider.tsx:962-982`
- **Logic**:
  1. Save session key
  2. Clear active_session_key from localStorage immediately
  3. Clear all auth artifacts (sync)
  4. Clear zustand store (sync)
  5. Set React state to UNAUTHENTICATED (sync)
  6. Redirect to login (sync)
  7. Fire remote cleanup in background (non-blocking)
- **Effect**: Login screen appears immediately (~0ms); remote cleanup runs asynchronously
- **Risk**: Minimal — remote cleanup is best-effort; local state is fully cleared regardless of remote outcome
- **Evidence**: The await on `logoutCurrentSecuritySession` could block up to 120s, proven in `PRACTICAL_LOGOUT_DELAY_TRACE.md`
