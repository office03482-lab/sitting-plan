## PHASE6B SCHOOL ONBOARDING REPORT

**Summary**

Phase 6B was implemented as an extension of the existing Platform Control Plane. The solution reuses the current Supabase-native auth/session model, the existing portal-access provisioning helpers, and the forced-password-change gate already present in the frontend.

No authentication redesign, RBAC redesign, scope-engine redesign, billing redesign, or ERP workflow rewrite was introduced.

**APIs Added**

- `POST /api/platform/onboarding`
  - Expanded request contract for school details, admin details, plan, and limits
  - Expanded response contract for admin identity, one-time credentials, provisioning status, and audit event list

- `POST /api/platform/schools/{school_id}/regenerate-admin-password`
  - Regenerates a school admin temporary password
  - Invalidates the previous temporary password immediately by resetting the Supabase auth password
  - Returns the new credential only once in the response payload

**Behavior Implemented**

- Platform Admin can provision a school with school profile + admin profile data in one workflow
- School setup seeds:
  - school metadata/settings
  - academic session metadata
  - default departments metadata
  - attendance settings row
  - role templates
  - school-admin permission template
  - usage snapshot
  - school plan
  - AI wallets
  - platform welcome notification

- School Admin account provisioning now creates:
  - Supabase auth account
  - profile
  - school membership
  - managed school-admin role
  - first-login metadata
  - forced password-change state

- Temporary credentials:
  - generated with a strong random password (`length=16`)
  - shown once in onboarding response
  - can be regenerated by Platform Admin
  - old temporary password becomes invalid immediately on regeneration because the auth password is rotated

- First login enforcement:
  - dashboard remains blocked while `must_change_password = true`
  - first-login page now acts as a guided onboarding wizard
  - after successful password completion:
    - `must_change_password = false`
    - `first_login_completed = true`
    - onboarding metadata is marked completed
